# Build 18 — Smart Permission Setup (standalone experiment)

Base: Build 17 ea1f94146b8354c4b5544671552238c9b1fa64a0. Do not merge into production until device validation. Build 17 capture/review unchanged.

User starts setup after reading the broad WRITE_SECURE_SETTINGS disclosure. Android 11+, Wi-Fi, Developer options and Wireless debugging required. Android 13+ notification consent required. Open Pair device with pairing code and enter the six-digit code in the Cherry notification. mDNS resolves only local-interface ADB services via libadb, sockets use loopback only. One fixed pm grant for the standalone package; no arbitrary shell interface, no remote hosts, no key files, no chat upload. Setup process is non-exported, temporary, isolated from capture, and terminated after finish/cancel/timeout. User must turn Wireless debugging off and forget the Cherry pairing. Setup is not a guarantee against OEM policy or permission revocation.

Dependencies: MuntashirAkon/libadb-android 3.1.1 (dual Apache-2.0 / GPL-3.0-or-later, upstream explicitly unaudited; transitive SPAKE2 license review needed before production), Conscrypt Android 2.5.3, Bouncy Castle bcpkix-jdk15to18 1.81. See https://github.com/MuntashirAkon/libadb-android and https://developer.android.com/tools/adb. The library requires INTERNET for local sockets and discovery; this changes Build 17's no-INTERNET manifest guarantee. Do not approve production without independent review and actual device test. No hidden API bypass. No remote command surface, persistent ADB or automatic service enabling.

Recovery is explicit foreground user button only; appends only own exact component to enabled accessibility services, preserves other component strings, checks concurrent modification before write, no global setting write or automatic re-enable. Android controls binding; if not ready use standard settings. WSS grant may survive reboot/in-place update but OEM policy may prevent it. Test with dummy chats only. No persistence of pairing code. ADB credential kept only in setup process memory; Android pairing record should be forgotten manually.

Device gates: first setup without other app; successful special grant check; turn off wireless debugging and forget pairing; clear recent apps; tap permission once; verify READY and Viber dummy capture; repeat and reboot; check manual OFF remains off until explicit tap; other accessibility services unchanged; cancel/timeouts/no network service after finish; fallback Settings works. If discovery/loopback fails, no claim of working setup. CI only compiles/tests pure logic, no real ADB pairing or OEM validation.
