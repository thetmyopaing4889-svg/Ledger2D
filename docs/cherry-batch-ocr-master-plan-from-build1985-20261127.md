## 1. Baseline and scope
- Approved Build 1985, commit afa77be118dd5b4c1129b3db6a3a35853e2badb6, workflow run 45960509723 (success).
- Isolate all OCR work on `feature/cherry-batch-ocr-from-build1985-20261127`. Never edit main or the approved source branch. Use separate benchmark APK application ID/storage; do not overwrite production data.

## 3. Non-negotiable acceptance and proposed targets
- After APK install, first recognition must work in airplane mode with bundled models and no key/account/download. Free personal use; verify licenses and retain required notices.
- Target warm mean <=1 s/image, batch wall time <=5/10/20 s for actual batches 5/10/20 images respectively, including decoding, segmentation, inference, sanitation and required fallback. Also report p50/p90/max, cold start (process/first initialization separated), time to review, manual end-to-end comparison. These are proposed goals, not measurements or guarantees; do not sacrifice correctness to meet them.
- No silent dropped/duplicated/misattributed lines, unreadable image, altered amount or automatic acceptance. All selected images have explicit outcomes; no partial batch accepted without explicit user exclusion and review. OCR is never the final accounting authority.
- No UI freezes, ANR, OOM, global navigation slowdown or persistent memory growth. Cancel and return to review safely. No production model loading until explicit OCR action; release after use/cancel.
- Proposed evaluation corpus: initial 20 unique samples, then 50–100+ distinct images including independent holdout. No ranking/engine winner until measured on user's Android device and review approved. Record proposed thresholds for device RAM/APK growth after baseline measurements and user agreement rather than inventing hard device budgets.

## 4. Stage A — isolated benchmark APK (first implementation)
Separate standalone test module or build variant with separate application ID, no ledger writes, no production storage access. Photo Picker/manual import; include consented/redacted or synthetic sample corpus. Real Messenger/Viber crops (light/dark), Myanmar/Latin/mixed numbers, leading zeros, R/BK, ခွေ/ပူး/ဘရိတ်/ထိပ်/ပိတ်/ပါ/အာ and all relevant existing format forms; single/multiline, spacing, punctuation, chat noise, long amounts, repeat lines, blurred/tiny/colored text, duplicate and unreadable cases. Ground truth per image: exact raw text, ordered line IDs, expected number/amount/format and expanded accounting pairs, intentional non-entry text. Do not commit real customer screenshots or amounts to GitHub. Use synthetic data for repo fixtures and locally curated anonymized validation. Separate tuning from holdout, do not edit ground truth to fit outputs.
Candidate matrix:
1. Tesseract Fast mya+eng.
2. Tesseract Best mya+eng (same native runtime/config as Fast, separate model files).
3. Bundled Google ML Kit Latin, primarily ASCII-only benchmark subset; explicitly count missed Myanmar on mixed cases, never assume Latin recognition proves absence of Burmese.
4. Myanmar CRNN INT8 ONNX: verify exact canonical model ID, pinned revision, license, charset, shape/normalization, CTC blank/decode, screenshot-to-line segmentation/order. Benchmark complete image-to-text path, not recognition alone. If not implemented mark NOT_RUN with reason.
PDF lists tesseract4android 4.7.0 and bundled ML Kit 16.0.1; newer compatible versions are candidates, not fixed choices. Before implementation verify official release/build ABI support, 16 KB native compatibility, runtime/minSdk/targetSdk and license. Pin library versions, model hashes, model source and configuration. No dynamic downloads in use. Test preprocessing original vs contrast/invert/resize; preserve aspect ratio, legibility, and line order. No mandatory double OCR on every image.
Benchmark protocol: same device and actual identical image IDs/order per engine; comparable crop/preprocessing variants clearly labeled. Time first load and warm-up separately; fresh process cold runs, repeated warm trials (propose 3+ cold, 5+ batch repeats); exact batch sizes, never label a smaller batch as 20. Time decode+preprocess+recognize+decode/segmentation+sanitize and end-to-end wall time; use monotonic clock. Track process PSS/native/Java memory baseline, sampled peak and after release; APK compressed size, installed size, model/runtime bytes, CPU/ABI/OS/device, thermal/battery observations. Include actual failures/timeouts and repeated trials, no fabricated values.
Report raw Unicode CER without silently changing digits, separate normalized CER/exact match; exact pair/amount/format per annotated line; missing/extra/duplicated lines via ordered alignment; expanded pair+amount map exactness via real parser fixtures; suspicious-flag recall and false alarms; per-image outcome and engine disagreements. Avoid regex extracting arbitrary numbers as amounts. Export JSON/CSV including engine ID/version/hash, input ID/hash, raw and normalized text, stage timings, statuses, error reason; local-only export on user request.
UI: choose images, select one engine or run comparison sequentially, start/cancel, actual progress, side-by-side source/text, per-image timing, summary/export. Benchmark test APK only; no release integration at this stage.
Gate A: install test APK, real airplane-mode measurements, corpus coverage and accounting accuracy review. Record NOT_RUN separately. No production OCR dependency before approval.

## 5. Stage B — selection and optimization
Select smallest sufficient single engine based on exact digit/amount/format and line completeness, p90/end-to-end speed and device cost. If one engine adequate, ship one. If not, evaluate a bounded hybrid on holdout; fast path only when language classification is credible, uncertain or mixed line use Myanmar-capable path. Retry only flagged image/line, max bounded retry; disagreements highlighted, never silently pick a number/amount based on confidence. Do not treat parser validity or engine agreement as proof. No unvalidated model in production. Consider custom OCR training only if real benchmark failures justify it.
Gate B: explicit user approval of selected engine, version/config, speed/quality tradeoff and APK impact.

## 6. Stage C — session state and image acquisition
Use persistent session record, proposed states: IDLE -> CAPTURING -> SELECTING -> RECOGNIZING -> REVIEW -> IMPORTED_DRAFT -> SAVED -> CLEANUP_PENDING -> COMPLETE; cancellation/error/retry branches. Store unique session ID, bound agent/customer/date/session/backdated/format, start/end timestamps, initial media baseline, frozen selected URIs and per-image status; persist editable draft and raw/normalized text privately, resume after process death. No automatic OCR while user is in Messenger/Viber. One active session; explicit resume/cancel before changing scope. If draw closes or profile removed, do not change scope automatically; use existing validation.
Start OCR from current Quick Entry input area after valid scope chosen; request image permission just in time. Notification optional; Android 13+ notifications may be denied, return via app/recent apps. Tap notification deep links to correct session via MainActivity/Compose Nav and handles cold/warm intents, not a nonexistent separate Input Activity. Persist scope independent of navigation. No foreground service just for capture.
MediaStore: start/end bounds and baseline IDs; DATE_ADDED seconds precision/ties and media indexing delay handled by review/refresh; folder/bucket name a hint only, not a strict filter. Include stable order (timestamp then ID), optional screenshot heuristic, explicit thumbnail confirmation for all candidates. Android 14+ partial access and denied/revoked permissions; Photo Picker multi-select fallback. No claim of automatic access if permission missing. No reading all gallery outside session window. X removes from selection only, never deletes. Freeze confirmed selected set and show count. Handle URI unreadable, duplicates (URI/hash warning, not automatic text dedup), unrelated images, no images, process death, reboot/clock change. Never scan old gallery if inactive or startTime missing.
Gate C: process death/resume, permission and notification matrix, no incorrect image inclusion without review, correct scope.

## 7. Stage D — production OCR pipeline and review
Sequential bounded work with coroutine cancellation, IO decode, dedicated CPU executor/Default, main UI progress; no concurrent reuse of unsafe native engine. Lazy load model once per active job/session, dispose in finally; downsample only safely and preserve text detail; free original and processed bitmaps, close streams, guard per-image dimensions and errors. Cancel does not falsely mark native recognition as stopped before it returns. Progress actual selected count, per-image outcome (pending/running/read/failed/excluded), retry only failed/selected. Keep raw text plus URI/crop/line provenance. Persist results to resume after interruption; no hidden skipped failures.
Sanitizer non-destructive: normalize Myanmar digits/whitespace where equivalent; explicit Unicode-aware term mapping tested against current parser; mark O/0, I/l/1, uncertain terms and timestamp/noise removals, preserve original and user correction. Never delete plausible number/amount text based on loose regex; do not infer amount, separators or format. Existing parser controls validity. Show thumbnail zoom/original and editable recognized lines, highlight missing/uncertain/disagreement/error, review all images, even apparently valid ones. Keep duplicates visible; repeated valid lines may be intentional. Import only explicitly reviewed text to current Input Box. If manual draft exists, ask append/replace/cancel; never overwrite silently. Existing format selection retained unless user chooses otherwise; test MANUAL mixed input and all supported format semantics, no automatic format guessing without review.
Gate D: validated text import, all failure states recoverable, no writes during capture/recognize/review.

## 8. Stage E — safe ledger integration and cleanup
Integrate narrowly in QuickEntryScreen/BettingScreen via OCR draft handoff and scope check; preserve existing layouts for normal entry and editing. Key import by session ID and draft version, reject stale mismatched preview. Use same refreshPreview, smartExpand, limits/closed number and confirm transaction; no separate OCR accounting path. User taps existing confirm; no auto-save. Associate successful receipt/entry ID with session plus exact reviewed image set; durable idempotency guard around retry/process death (design with existing repository transaction; no duplicate entries). Do not clear text or cleanup eligibility on failed save. Confirm explicitly if changed scope/format/input after OCR. Backdated behavior remains opt-in existing rules.
Only after verified successful save offer "ဖတ်သွင်းပြီးသော Screenshot (N) ပုံ ဖျက်မည်"; list exactly accepted source images attributable to saved draft. Excluded, failed, unread, unrelated, cancelled or not-yet-saved images must remain. User can keep all. Android 11+ MediaStore.createDeleteRequest, system confirmation; older/partial access use supported permission-safe fallback or manual delete, never pretend deleted. Handle cancel/partial/failure and report actual status; no broad folder cleanup. Retain private session metadata minimally, purge temporary OCR data when appropriate, preserve financial audit. No raw screenshots in logs/telemetry/backup by default.
Gate E: successful/failed save, stale preview, duplicate tap/reopen, limit/past draw, cleanup cancellation, scope mismatch and unchanged financial totals on baseline fixtures.
